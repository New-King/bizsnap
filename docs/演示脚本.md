# 演示脚本

> 下文的预期结果是按实际运行校准的（括号里是真实输出片段）。

## 准备

从空库开始，不需要预置数据：

1. 设置页点「清空全部数据」，把服务端库、系统通讯录里本应用建的联系人、系统日历里本应用写的会议一起清掉
2. 新建第一个会话

Case 1 会先建出王建国；Case 2、Case 3 用的李静与陈默，走 Case 1 之外的正常对话（如「李静已经从 C 公司跳到 D 公司了」）也能自己攒出来。要演「李静换过公司、陈默现在在做跨境支付」这种对照，按正常流程各聊一轮并确认即可。

## Case 1：截图 → 卡片

**输入**：一张商务聊天截图，内容包含对方姓名、公司、职位、约见时间。

**预期**：

- agent 文字**逐字出现**；正文流完、这条消息落定后，卡片才出现（卡片不会抢在文字前面）
- 文字说清「建谁、什么公司职位、约在什么时间、去哪里」
- 出现两张卡片：创建联系人、创建会议
- 勾选两张 → 「确认选中 2 项」→ 确认 → 卡片折叠成「已写入通讯录 ›」
- 打开系统通讯录能看到这个人，打开日历能看到这场会

**演示点**：同一段输入同时产出两种动作；卡片本身不显示字段，信息全靠正文。

## Case 2：跨会话找人

**输入**：新建一个会话，只说一句「上次做跨境支付那个，最近有联系吗」。

**预期**（实测）：

> 我查到两个符合「跨境支付」的人，请确认是哪一位：
> 1. **陈默** — C 公司，支付产品负责人，项目：跨境支付（2026-02-01 起）
> 2. **李静** — 现为 D 公司运营总监；2025-03-01 至 2026-01-31 在 C 公司做过跨境支付项目，现在项目是仓储自动化

- agent 自己调用检索，不出现「没找到」
- 一句话就让用户确认是哪一位，没有自己瞎猜

**演示点**：新会话没有上下文，靠检索把人捞回来；关键词 + 向量只用来找是谁，事实全部来自数据库。

对照：在同一会话追加「**现在**谁在做跨境支付」，实测只报陈默，并补一句李静的项目什么时候结束的——`when='now'` 生效。

## Case 3：他换公司了

**输入**：「李静已经从 C 公司跳到 D 公司了，还在管供应链，项目也从供应链优化换成了仓储自动化」。

**预期**（实测）：

- 正文写清「公司：C 公司 → D 公司；项目：供应链优化 → 仓储自动化」，并说明职位没提到新头衔所以保留
- 出现一张「更新联系人」卡片
- 确认后 `attributes` 里 `company.value = D 公司`、`since = 今天`，`history` 多出 `C 公司` 那段；`project` 的两段历史都留着
- 确认后卡片立刻折叠，`insight` 逐字流成一条 agent 文字，实测：
  > 李静自 2023-05-01 起是客户，2026-10-29 从 C 公司换到 D 公司、项目由供应链优化转为仓储自动化，上次见面是 2026-08-20。建议在 2026-11-05 前约李静确认 D 公司仓储自动化项目的对接人和推进时间。

**演示点**：属性是覆盖的，历史不丢；下一次检索用旧公司名也能找到他，且能看出那是「以前」；洞察是在**确认之后**才生成的，用的是刚写入的事件 + 完整时间线。

## 收尾：确认才会有记忆

实测：输入「今天认识了孙浩，他是恒瑞资本的法务顾问，约了他明天下午两点线上聊合同条款」后，卡片出现但先不确认，`contacts` 表里查不到孙浩（`select count(*) from contacts where name='孙浩'` → 0）；退出再进会话，聊天记录与卡片都还在。用来讲「工具不写库，只有确认才落」这条线。

## 非商务输入

输入「哈哈哈今天好累啊，晚上吃啥」，实测回复就是四个字「未识别到商务信息」，不调工具、不出卡片。
